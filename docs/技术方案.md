---

## 1. 项目概述

面向家庭用户的家电清洗与维修上门服务平台,连接**用户、师傅、商家、平台**四方。

### 1.1 四端形态(严格按树状图)

| 端 | 文件 | 形态 | 说明 |
|----|------|------|------|
| 用户端 | `index.html` | Web 页面 | 预约下单、订单查询 |
| 师傅端 | `master.html` | Web 页面 | 抢单、完工收款、收入管理 |
| 商家端 | `merchant.html` | Web 页面 | 代报订单、佣金、推广二维码 |
| 后台端 | `admin.html` | Web 页面 | 全局管理、派单、财务、统计 |

### 1.2 核心业务闭环

预约下单 → 接单/派单 → 上门服务 → 完工收款 → (评价)

### 1.3 三种订单来源

- `user_self`:用户自主下单
- `merchant_report`:商家代报(含推广归属逻辑)
- `master_create`:师傅自建单

## 2. 技术栈(按树状图)

### 2.1 技术选型

| 层级 | 技术 | 说明 |
|------|------|------|
| 前端四端 | **原生 HTML + CSS + JS** | 单 HTML 文件,内嵌样式与脚本,无需构建 |
| UI 组件 | 手写或轻量库(如 Tailwind CDN) | 保持单文件简单性 |
| 后端 | **Node.js(Express)** | 单 `server.js`,RESTful API |
| 数据存储 | **JSON 文件(data.json)** | 按树状图设计;建议生产环境升级 SQLite 解决并发 |
| 认证 | **JWT + Cookie(HttpOnly)** | 多角色登录 |
| 二维码 | qrcode 库(前端生成) | 商家推广二维码 |
| 图片上传 | Base64 存 JSON 或独立文件目录 | 完工照片、评价图片 |
| 静态托管 | Express 静态服务 | 托管四个 HTML 页面 |

### 2.2 项目结构

```
project/
├── index.html              # 用户端
├── master.html             # 师傅端
├── merchant.html           # 商家端
├── admin.html              # 后台端
├── server.js               # 后端服务(单文件)
├── data.json               # 数据存储
├── package.json
├── backups/                # 数据备份目录
└── uploads/                # 图片上传目录(可选)
```

### 2.3 与树状图的一致性说明

- 四端 HTML 文件名、职责与树状图完全一致
- `server.js` 的 API 路由与树状图列出的接口一一对应
- `data.json` 的数据结构按树状图功能反推
- **不引入**小程序、App、NestJS、MySQL、Redis、微信支付(均偏离树状图)

### 3.2 鉴权方案

- **JWT 写入 HttpOnly Cookie**:防 XSS
- **多角色区分**:token payload 含 `role: user/master/merchant/admin` + `id`
- **中间件守卫**:`requireAuth`、`requireRole('master')` 等
- **小程序场景无**(树状图无此要求)

## 5. API 接口设计(对齐树状图 server.js)

### 5.1 通用规范

- Base URL:`/api`
- 响应格式:`{ code: 0, message: "success", data: {} }`
- 鉴权:Cookie 中的 JWT
- 路由完全对应树状图 server.js 列表

### 5.2 认证模块 `/api/auth`

| 方法 | 路径 | 说明 | 鉴权 |
|------|------|------|------|
| POST | /api/auth/master | 师傅登录 | 否 |
| POST | /api/auth/merchant | 商家登录 | 否 |
| POST | /api/auth/admin | 管理员登录 | 否 |
| POST | /api/auth/logout | 登出 | 是 |
| GET | /api/auth/me | 获取当前用户 | 是 |
| PUT | /api/user/password | 修改密码 | 是 |

### 5.3 订单模块

| 方法 | 路径 | 说明 | 鉴权 |
|------|------|------|------|
| GET | /api/orders | 订单列表(按角色返回) | 是 |
| POST | /api/order | 创建订单 | 是 |
| PUT | /api/order/:id | 更新订单(接单/完工/取消/分配) | 是 |
| DELETE | /api/order/:id | 删除订单 | admin |

> 接单、完工、取消、分配等操作通过 `PUT /api/order/:id` 配合 `action` 字段实现,或拆分子路由(见 5.3.1)。

#### 5.3.1 订单动作明细

| 动作 | 实现方式 | 说明 |
|------|----------|------|
| 接单 | PUT /api/order/:id `{action:"accept"}` | 校验配额、配额+1、状态变更 |
| 拒单 | PUT /api/order/:id `{action:"reject", reason}` | 状态变更为 cancelled |
| 取消 | PUT /api/order/:id `{action:"cancel", reason}` | 释放配额(若已接单) |
| 完工 | PUT /api/order/:id `{action:"complete", actualAmount, images, remark}` | 核心资金流 |
| 分配 | PUT /api/order/:id `{action:"assign", masterId}` | 后台指派 |

## 6. 各端功能模块(严格对齐树状图)

### 6.1 用户端(index.html)

#### 6.1.1 首页(Home)
- 服务数据看板:已服务家庭数、覆盖小区数、好评率、入驻师傅数
- 服务项目快捷入口:点击自动跳转预约页并选中类型
- 快速预约卡片
- 服务流程展示(预约→接单→上门→完工)
- 服务优势展示

#### 6.1.2 预约下单(Order)
- 表单填写:
  - 客户姓名(必填)
  - 手机号(必填)
  - 详细地址(必填 + 本地历史地址快捷填充)
  - 服务类型/项目(点击弹出选择器)
  - 预约时间(点击弹出时间选择器,限制 08:00-20:00)
  - 备注
- 协议确认:
  - 免责协议(弹窗)
  - 平台协议(弹窗)
  - 勾选同意(必选)
- 价格参考显示
- **推广归属逻辑(核心)**:
  - 自动检测 URL 参数 `?merchant=xxx`
  - 存储到 localStorage
  - 下单时自动设置 `source="merchant_report"`
  - 自动设置 `creator=商家名称`
  - 自动应用后台统一配置的介绍费率
- 提交预约 → 成功后展示订单号

#### 6.1.3 订单查询(Query)
- 输入手机号
- 获取验证码(模拟)
- 验证并查询
- 订单列表展示(按时间倒序):
  - 显示:服务类型/项目、状态、客户名、地址、预约时间、师傅、金额
  - 待接单状态可「取消订单」
- 订单详情弹窗:
  - 订单号、下单时间、预约时间
  - 服务信息、客户信息、地址
  - 实收金额、服务费、介绍费
  - 完整时间线(下单/接单/完工/取消等)

#### 6.1.4 评价(本版新增)
- 完工后订单卡片显示「去评价」入口
- 评价页:三维评分(态度/专业/准时)+ 文字 + 图片
- 提交后订单状态变为 `evaluated`

### 6.2 师傅端(master.html)

#### 6.2.1 抢单池(Pool)
- 顶部状态栏:
  - 当前时段(上午/下午/晚间)
  - 今日剩余可接单数
- 待接单列表:
  - 显示:服务类型/项目、客户名、电话、地址、预约时间
  - 过期订单标记(已过期)
- 接单操作:
  - 校验当前配额(配额用完则禁用)
  - 更新师傅配额(usedMorning/Afternoon/Evening +1)

## 7. 核心业务流程(对齐树状图)

### 7.1 预约下单流程(含推广归属)

```
用户访问 index.html
   │
   ├─ [场景A] 直接访问 → source = user_self
   ├─ [场景B] URL 带 ?merchant=mt_001
   │    ├─ 检测参数,存 localStorage
   │    ├─ 下单时 source = "merchant_report"
   │    ├─ creator = 商家名称(查 merchants 表)
   │    └─ merchantId = mt_001
   │
   ├─ [场景C] 商家端代报 → source = merchant_report
   ├─ [场景D] 师傅自建 → source = master_create
   │
   ▼
POST /api/order
   │
   ├─ 校验时间(08:00-20:00)
   ├─ 计算 timeSlot(morning/afternoon/evening)
   ├─ 若有 merchantId:快照 referralRate(从 config 读)
   ├─ 生成 orderNo
   ├─ status = pending
   ├─ 写 timeline(create)
   └─ 返回订单号
```

### 7.2 接单流程(树状图核心:配额校验)

```
师傅点击「接单」
   │
   ├─ 校验师傅在线状态
   ├─ 校验当前时段配额:used < quota
   │   ├─ 不足 → 禁用接单按钮,提示「配额已满」
   │   └─ 充足 → 继续
   ├─ 更新订单:masterId = 当前师傅,status = accepted
   ├─ 配额 +1(usedMorning/Afternoon/Evening)
   ├─ 记录 acceptedAt
   ├─ 写 timeline(accept)
   └─ 返回成功
```

### 7.3 完工收款流程(树状图核心:资金流)

```
师傅点击「完工收款」
   │
   ├─ 输入实收金额 actualAmount
   ├─ 上传完工图片(压缩 Base64)
   ├─ 填写完工备注
   │
   ▼
PUT /api/order/:id {action: "complete"}
   │
   ├─ 读取 config.serviceFeeRate(如 10%)
   ├─ 读取订单 referralRate(下单时快照,如 5%)
   ├─ 计算:
   │   ├─ serviceFee = actualAmount * serviceFeeRate / 100
   │   └─ referralFee = actualAmount * referralRate / 100(若有商家)
   ├─ 师傅余额 -= serviceFee
   ├─ 平台余额 += serviceFee
   ├─ 商家余额 += referralFee(若有)
   ├─ 师傅 totalIncome += actualAmount
   ├─ 师傅 totalFee += serviceFee
   ├─ 写 3 笔 transactions(master/platform/merchant)
   ├─ 订单 status = completed
   ├─ 记录 completeAt、actualAmount、serviceFee、referralFee
   └─ 写 timeline(complete)
```

> **注意**:树状图设计是师傅手填实收金额,资金不经过平台。平台通过扣师傅余额收取服务费,商家通过加余额获得介绍费。**不引入在线支付**。

### 7.4 超时自动取消

```
定时任务(每 10 分钟执行)
   │
   ├─ 读取 config.autoCancelHours(默认 36)
   ├─ 查询 status=pending 且 createdAt < now - autoCancelHours 的订单
   ├─ 批量更新 status = cancelled
   ├─ 写 timeline(系统自动取消)
   └─ (可选)通知用户
```

### 7.5 配额每日重置

```
定时任务(每日 00:00 执行)
   │
   ├─ 查询 quotaDate != today 的师傅
   ├─ 重置 usedMorning = 0、usedAfternoon = 0、usedEvening = 0
   └─ quotaDate = today
```

### 7.6 提现流程

```
商家/师傅 申请提现
   │
   ├─ POST /api/withdrawal
   ├─ 校验余额充足
   ├─ 余额 -= amount(冻结)
   ├─ status = pending
   │
   ▼
后台审核
   │
   ├─ 通过 → 上传转账截图 → status = transferred
   └─ 拒绝 → 退还冻结金额 → status = rejected
```

### 7.7 充值流程

```
师傅 申请充值
   │
   ├─ POST /api/recharge/request(含凭证截图)
   ├─ status = pending
   │
   ▼
后台审核
   │
   ├─ 通过 → 师傅余额 += amount → status = approved → 写 transaction
   └─ 拒绝 → status = rejected
```

## 8. 评价体系设计(本版新增)

### 8.1 评价时机

- 订单状态为 `completed` 后,用户端订单卡片出现「去评价」入口
- 评价后订单状态变为 `evaluated`
- 一个订单只能评价一次

### 8.2 评价维度

| 维度 | 字段 | 分值 |
|------|------|------|
| 服务态度 | scoreAttitude | 1-5 |
| 专业度 | scoreProfessional | 1-5 |
| 准时度 | scorePunctual | 1-5 |
| 综合评分 | scoreAvg | 三项平均,保留 1 位小数 |

### 8.3 评价内容

- 文字:最多 500 字
- 图片:最多 6 张(Base64 存储或上传目录)
- 匿名:勾选后师傅端不显示评价人手机号

### 8.4 评价展示

| 端 | 展示位置 |
|----|----------|
| 用户端 | 订单详情显示评价;首页好评率统计 |
| 师傅端 | 「我的评价」:查看所有评价、平均分、回复评价(一次) |
| 后台 | 评价管理列表:按师傅/评分筛选、隐藏违规评价 |

### 8.5 评分统计更新

评价提交时,同步更新师傅的 `ratingAvg` 和 `ratingCount`:

```js
master.ratingAvg = (master.ratingAvg * master.ratingCount + newScore) / (master.ratingCount + 1);
master.ratingCount += 1;
```

## 10. 部署方案

### 10.1 部署架构(轻量)

```
┌─────────────┐
│  域名 + SSL  │  (Nginx 或云服务器自带)
└──────┬──────┘
       │
┌──────▼──────┐
│   Node.js   │  server.js (PM2 守护)
│   Express   │  端口 3000
└──┬───────┬──┘
   │       │
┌──▼──┐ ┌──▼──────┐
│data │ │backups/ │
│.json│ │uploads/ │
└─────┘ └─────────┘
```

### 10.2 部署步骤

1. 服务器安装 Node.js 18+
2. `npm install` 安装依赖
3. `pm2 start server.js --name appliance-platform`
4. Nginx 反向代理到 3000 端口,配置 SSL
5. 初始化 `data.json`(预置 admin 账号、config、示例服务项目)

### 10.3 数据备份

- **手动备份**:后台仪表盘一键备份,`data.json` 复制到 `backups/data-YYYYMMDD-HHmm.json`
- **自动备份**:crontab 每日凌晨备份
- 保留最近 30 个备份

### 10.4 生产环境建议

- 将 `data.json` 升级为 SQLite(单文件、支持事务、并发安全)
- 图片改存 `uploads/` 目录或 OSS,避免 JSON 膨胀
- 接入短信服务(替换模拟验证码)
